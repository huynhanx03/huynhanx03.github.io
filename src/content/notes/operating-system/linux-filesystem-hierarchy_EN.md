Linux brings multiple filesystems and data sources into one tree starting at `/`. Standard directory names help administrators know where to find configuration, logs, executables, or kernel state; distributions may differ in details and symlinks.

## Common directories

- `/etc`: system and service configuration.
- `/var`: changing data such as logs, spool files, caches, or database state.
- `/usr`: most programs, libraries, and shared data; operationally read-only on many distributions.
- `/home`: ordinary user data.
- `/root`: the superuser's home directory.
- `/tmp`: temporary files, which may be cleaned up.
- `/run`: runtime state, commonly on tmpfs.
- `/dev`: device nodes.
- `/proc`: virtual process and kernel interface.
- `/sys`: virtual device/kernel topology and attributes.

The Filesystem Hierarchy Standard is general guidance; distributions have their own layouts. Do not delete a file in `/var` just because its name looks like cache or logs until you know which service owns it.

## procfs and sysfs are not persistent data

`/proc` provides process information (`/proc/<pid>`) and kernel parameters; some files can change runtime settings. `/sys` exposes devices, drivers, buses, and tunable attributes. Their contents are generated by the kernel when read, not ordinary saved files on disk.

Some files have side effects when written. Use `sysctl` for supported kernel parameters under `/proc/sys`; attributes in `/sys` need the subsystem’s own tool or interface. Read kernel or distribution documentation before changing settings.

## Package ownership

Files under `/usr` are commonly owned by a package manager. Editing a packaged binary directly may be overwritten during an update and make checksums or verification fail. Put configuration overrides in paths supported by the service, such as drop-ins, instead of editing vendor files.

## Summary

- Standard directories suggest a role, but details can vary by distribution.
- `/etc` holds configuration, `/var` changing data, and `/usr` shared programs and data.
- `/proc` and `/sys` are virtual kernel interfaces, not persistent file stores.
- Some virtual files have side effects when written.
- Package-owned files may be overwritten by updates; use the supported override mechanism.

## Check your understanding

**Is `/proc/cpuinfo` stored permanently on a disk?** No; procfs generates kernel information.

**Are files in `/tmp` guaranteed to survive a reboot?** No.

**Is editing a binary in `/usr/bin` a way to configure an application?** Usually not; use the appropriate configuration, service override, or package mechanism.
